## Automatic wallpapers, native Omarchy controls

SwiftWall rotates wallpapers from your chosen local folders and puts Previous,
Pause/Resume and Next controls in your Omarchy bar. It uses Omarchy's existing
wallpaper renderer and never modifies your original images.

This first stable downloadable release is planned to include a prebuilt Linux
x86_64 engine and a terminal setup wizard. **Users do not need Rust, Cargo or a
repository clone.**

### Highlights

- Five-minute shuffle rotation by default, avoiding immediate repeats and exhausting
  the shuffle bag before reshuffling; optional sequential selection.
- JPEG, PNG and WebP from multiple nonrecursive local folders.
- A native pop-out controller, optional countdown, folder drafts, Save and Revert.
- A short-lived external portal helper for the native folder chooser.
- Existing wallpaper preserved at startup; manual wallpaper changes reset the timer
  without clearing an explicit pause.
- Durable carousel history, pause and shuffle state, checked through shutdown/restart.
- User-local setup with verified downloads, ownership checks, configuration-before-
  start, bounded service readiness, backups and failure recovery.
- Image-safe uninstall, retaining configuration/state by default.

## Planned stable Quick Install — not available yet

Only once the approved stable 0.2.0 assets are built, validated and published:

1. Download the Linux x86_64 archive and `SHA256SUMS` from this release into a new
   folder. Open a terminal there and continue only when verification reports `OK`:

   ```sh
   sha256sum --check SHA256SUMS
   ```

2. Extract the archive with your file manager into your own non-shared directory.
   Open a terminal inside `swiftwall-0.2.0/` and run:

   ```sh
   ./swiftwall-setup install
   ```

3. Enter each local wallpaper folder without shell quotes; a blank line finishes
   the list. Accept 300 seconds and Shuffle for the defaults. Answer `y` when asked
   whether to enable the bar widget, review the plan, then type `install` to confirm.
   Complete the panel/countdown/control check when prompted.

Run as your ordinary logged-in Omarchy user, **not with sudo**. Keep the extracted
setup folder for later maintenance. Installation checks requirements but does not
install system packages or upgrade Omarchy.

Requirements: Linux x86_64, Omarchy/Hyprland, Python 3.11+, systemd user services,
`busctl`, `ss`, `findmnt`, PyGObject/Gio (`python-gobject` on Arch), and a working
XDG Desktop Portal FileChooser backend. New network/GVFS/FUSE collections are not
supported. Local subfolders must be selected individually.

## Status, updates and uninstall

From the retained setup folder:

```sh
./swiftwall-setup status
./swiftwall-setup uninstall
```

For an existing supported owned installation upgrading to this release, obtain,
verify and extract this newer bundle, then run its helper:

```sh
./swiftwall-setup update --version 0.2.0 --dry-run
./swiftwall-setup update --version 0.2.0
```

Use an exact approved version for future releases. Updates preserve wallpaper
folders, settings, history, pause and existing service enablement/running state.
The portable helper is not silently self-updated; use a newer downloaded setup
bundle to obtain newer installer code or a changed release contract.

Uninstall never removes wallpaper images. Configuration/state remain unless you
explicitly choose `uninstall --remove-data`. That option removes only the known
settings/state files; private recovery backups and the extracted setup bundle
remain for separate review/removal. It is not secure erasure.

## Important limitations and recovery

- **Changed QML/helper or structural plugin updates are refused before mutation.**
  Identical payloads and safe version/descriptive metadata-only changes are
  supported. Future changed-QML releases require a separately tested migration;
  SwiftWall does not restart Quickshell to bypass component caching.
- Modified/unowned engine/plugin files are refused. An Omarchy Git-managed plugin
  directory is not automatically adopted. Do not manage the same plugin directory
  with both installers; inspect and migrate it deliberately.
- Automatic recovery handles ordinary setup failures within the operation.
  **Cross-process rollback is manual; there is no automatic cross-process `rollback`
  CLI.** Interrupted/power-loss cases require reviewing retained private backups.
  Never restore an old wallpaper snapshot over the currently active selection.
- Filesystem calls stuck in uninterruptible kernel I/O cannot be cancelled by a
  userspace timeout. Plugin tree and ownership metadata are not one power-loss-
  atomic transaction.
- Setter success is not proof of visual rendering; status reports visual
  verification as unknown. Omarchy's setter interface cannot eliminate every
  external-application race.
- No thumbnails, recursive discovery, per-monitor configuration or replacement
  renderer. The panel does not yet show an aggregate image-count label; status
  reports that count.

The release documentation should link the finalized setup, security, recovery and
advanced source-build guides. Troubleshooting should start with setup status and
read-only logs, not repeated enable requests or shell restarts.

## Why the marketplace says Manual setup

The marketplace installs plugins; it does not provision SwiftWall's mandatory Rust
engine and user service. The prebuilt setup bundle simplifies that separate step
but does not change the marketplace contract. **Manual setup remains intentional.**
Marketplace verification covers its exact reviewed snapshot, not automatically this
new tag or GitHub Release. A stable marketplace update requires separate approval
and maintainer verification.
